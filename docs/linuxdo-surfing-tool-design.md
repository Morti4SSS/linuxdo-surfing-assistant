# Linux.do 冲浪 Skill 设计

日期：2026-05-30

## 目标

做一个任务型 Linux.do 冲浪 skill，用 Codex 内置浏览器读取需要登录态的帖子，帮助用户增强 AI 相关信息搜集能力。

它不是论坛爬虫，也不是固定日报生成器。它的核心是让 Codex 按任务消耗 token 去阅读、筛选、提炼、沿着帖子里的有价值线索延展冲浪，并沉淀结果。`tools/linuxdo_surf.py` / `scripts/linuxdo_surf.py` 只是状态、队列和 session 辅助脚本，不是冲浪主体。

## 核心约束

- Linux.do 内容依赖登录态，第一版只通过 Codex 内置浏览器或已登录浏览器会话读取。
- 不做无差别全站抓取，避免 token、时间和误判成本失控。
- 每轮冲浪必须有明确模式、预算和输出边界。
- 当 skill 与 `/goal` 联用时，任务不是单次总结，而是持续迭代：读帖、提取线索、扩展下一批、保存 session，直到停止条件满足。
- 本地只保存必要状态：已读记录、候选记录、证据包、skill 管理同步状态。
- Skill 管理项目只消费冲浪结果，不承担论坛阅读职责。

## 四种使用模式

### 1. 选题研究模式

用户提供主题，工具围绕主题找相关帖子并阅读。

输入示例：

- Codex 长任务工作流
- skill 路由治理
- Trellis 是否值得用
- AI 编程如何做架构审查

输出：

- 值得读的帖子列表
- 每个帖子的核心观点
- 高赞回复里的补充和反对意见
- 提到的工具、skill、插件、工作流
- 对用户当前阶段的行动建议

### 2. 无目标淘金模式

用户不给具体主题，工具在预设范围内自主冲浪。

预设范围：

- AI Coding
- Codex / Claude Code / Gemini CLI / OpenCode
- skill / 插件 / MCP
- 工作流 / harness / 长任务
- 开源工具 / 自荐项目
- 经验反思 / 踩坑 / 成本控制

输出：

- 本轮发现的高价值帖子
- 值得深读的主题
- 只是热闹但暂不行动的内容
- 可以加入后续追踪的工具或项目

### 3. Skill 反响查询模式

输入一批 skill 名称，从 Linux.do 查推荐、吐槽、对比、替代方案。

输入来源：

- 用户手动给列表
- skill 管理项目导出的待评估 skill
- skill 管理项目中未查询社区证据的条目

输出字段：

- `skill_name`
- `topic_links`
- `positive_feedback`
- `negative_feedback`
- `comparison_notes`
- `risk_notes`
- `trial_recommendation`
- `sync_target`

其中 `sync_target` 用来标记是否适合同步回 skill 管理项目的 `community/skill_reviews.json`。

### 4. 优秀 Skill / 工作流发现模式

主动寻找最近被推荐的 skill、插件、CLI、workflow、harness 或配置方案。

输出：

- 新候选名称
- 来源帖子
- 解决的问题
- 适合放入 skill 管理、工具库，还是只收藏
- 是否需要 GitHub 进一步核验
- 是否可能和现有 skill 重复或冲突

## 推荐架构

### 浏览器阅读层

职责：

- 使用 Codex 内置浏览器或已登录浏览器会话打开 Linux.do。
- 执行站内搜索、打开帖子、读取首帖和高价值回复。
- 保持登录态读取，不把私有登录态内容交给普通无状态爬虫。

### 操控通道层

职责：

- 根据任务来源选择合适的浏览器或自动化入口。
- 把“Codex 主动冲浪”和“用户已经筛选好的帖子阅读”分开处理。
- 记录每轮任务使用的操控通道，方便复盘阅读成本和结果质量。

第一版通道：

- `codex-browser`：默认通道。使用 Codex 内置浏览器读取 Linux.do，适合选题研究、无目标淘金、skill 反响查询、优秀 skill / 工作流发现。首次需要用户登录 Linux.do，后续复用保存的登录态。
- `user-chrome`：辅助通道。使用用户本机 Chrome 中已经打开或已按标签组整理的帖子，适合用户先人工筛选，再让 Codex 读取、理解页面关系、总结和沉淀。这个通道不承担全站搜索职责。

后续执行形态：

- `mac-goal`：`/goal` 长跑执行形态。用于“持续冲浪直到满足标准”的任务，例如找到足够多高价值帖子、补齐指定 skill 的评价、发现一定数量的新工作流。它不是独立阅读通道，读帖仍依赖 Codex 内置浏览器和登录态。必须带停止条件、预算和阶段性汇报，不做无限继续。

通道选择规则：

- 用户没有指定帖子或页面时，优先 `codex-browser`。
- 用户已经在 Chrome 打开、筛选或用标签组整理帖子时，优先 `user-chrome`。
- 用户明确要求一直冲浪直到某个标准完成时，才考虑 `/goal` 执行形态。

### 任务调度层

职责：

- 接收四种模式的任务输入。
- 控制每轮阅读预算，例如候选帖子数、深读帖子数、回复读取数量。
- 跳过已读或低价值重复内容。

### 提炼层

职责：

- 把帖子内容提炼成结构化结果。
- 区分事实、作者观点、回复共识、个人行动建议。
- 标记置信度和证据链接。

### 存储层

职责：

- 保存已读 topic。
- 保存候选 topic。
- 保存本轮结果。
- 保存可同步给 skill 管理项目的证据包。

第一版可以使用 JSON / JSONL，后续如果查询和去重复杂，再切 SQLite。

### Skill 管理导出层

职责：

- 把和 skill 相关的证据转成 skill 管理项目可消费的社区证据。
- 不直接改变 skill 开关。
- 不替用户安装 skill。

## 输出形态

第一版不做固定本地日报。

每次任务只输出“本轮结果”，并按模式决定是否保存：

- 选题研究：保存主题研究结果。
- 无目标淘金：保存本轮淘金结果和后续追踪候选。
- Skill 反响查询：保存 skill 证据包。
- 优秀 skill / 工作流发现：保存候选工具和反哺建议。

以后如果接 Telegram 或微信机器人，可以把这些“本轮结果”推送出去，但推送不是第一版主线。

## 平台选择

第一版优先 Windows。

理由：

- 当前已有 Windows PowerShell + CDP 原型。
- 现有输出目录已经有 Linux.do 调研结果。
- 可以直接复用当前工作区和 skill 管理项目。

Mac 作为后续增强方向：

- 如果需要 `/goal`、Herme 或更强的系统级自动化，再迁移或做跨平台入口。
- 机器人推送和常驻任务可以等核心阅读闭环稳定后再做。

## 第一版范围

做：

- 四种任务模式的命令入口或轻量本地入口。
- 通过登录态浏览器读取 Linux.do。
- 搜索、候选排序、深读、结构化提炼。
- 保存已读和证据包，避免重复阅读。
- 支持把 skill 相关证据导出给 skill 管理项目。

不做：

- 固定日报系统。
- 全站爬虫。
- 自动安装 skill。
- 自动修改 CCSwitch 开关。
- Telegram / 微信机器人。
- 无限无人值守后台冲浪。

## 验证方式

- 用一个用户指定选题跑通选题研究模式。
- 用一次无目标淘金跑出 5 到 10 个候选。
- 用 skill 管理项目中的 3 到 5 个 skill 跑通反响查询。
- 至少发现 1 个新 skill 或工作流候选，并给出是否反哺的判断。
- 确认重复运行不会反复深读同一帖子。
