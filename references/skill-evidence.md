# Skill Evidence

Use this reference when Linux.do surfing should feed a skill management project.

## Evidence Package

For each skill, tool, plugin, or workflow candidate, preserve:

- `skill_name` or candidate name;
- topic links;
- positive feedback;
- negative feedback;
- comparison notes;
- risk notes;
- trial recommendation;
- whether GitHub or official documentation needs verification.

The surfing skill should not install, enable, disable, or rewrite skill settings by itself. It collects community evidence and produces a package that the skill management project can consume.

## Recommendation Levels

Use plain recommendations:

- `建议试用`: clear positive feedback and low risk;
- `可小范围试用，注意风险`: useful but has conflicts, setup cost, or mixed feedback;
- `仅记录证据，暂不建议启用`: weak evidence, mostly noise, unclear benefit, or significant risk.

## What Counts As Useful Evidence

Useful evidence includes real usage reports, failure cases, comparisons with alternatives, long-term updates, setup friction, conflict with other skills, and comments from high-signal authors. A single enthusiastic mention is a lead, not proof.

When the user asks to check many skills, prioritize those with conflicting or repeated community mentions. If a skill has no Linux.do evidence, say so and do not invent community feedback.
